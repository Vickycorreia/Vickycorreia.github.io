01 / TWO BOARDS, ONE CHAIN

From a sensor to a letter

Context
Six-person academic project, 2026.
My role
Embedded processing and logic, with Tristan.
Link direction
Transmitter → receiver; unidirectional communication.

One piezo is assigned to dots, the other to dashes. The transmitter needs to turn detected impacts into consistent pulses. The receiver then needs to measure active periods and gaps to reconstruct characters; an I²C OLED is intended to display them.

Dots and dashes use the same 433.92 MHz carrier. Their meaning comes from duration: OOK switches the carrier on and off. The system does not use a different radio frequency for each Morse symbol.

01 / TWO BOARDS, ONE CHAIN

One gesture.One message.

Two piezos, two STM32 boards and a 433.92 MHz radio link. The aim: turn taps into dots and dashes, then recover readable letters on a display.

  • Piezos
  • STM32
  • 433.92 MHz
  • OOK

The approach

Connect the blocks. Keep the signal meaningful.

The starting point is deliberately simple: tap one of two piezo sensors to enter a dot or a dash. Behind that gesture sits a complete chain: an input to interpret, a duration to generate, a radio carrier to switch and letters to reconstruct. Our six-person team divided the work into these blocks. With Tristan, I worked on embedded processing and logic. The first question was what each block should receive and deliver to the next one. A development-board prototype let us check Morse timing and interpretation ahead of final integration. The two photographed PCBs make the architecture tangible; fabricating them did not, by itself, validate the complete radio link.

The approach

A tap needs to become a clear event

A piezo sensor responds to vibration. The software needs to turn that response into a usable event, then generate a short or long symbol. The challenge is to separate an intended tap from unwanted signals without triggering several times. The prototype helps establish the logic; measurements on the transmitter board then reveal what actually arrives from the sensor. The report describes a piezo signal sent and measured on the custom PCB. That is a concrete acquisition result, but it does not demonstrate radio transmission successfully decoded at the other end. A simple way forward is to check the input, symbol duration and radio-module output as three separate parts.

03 / RECEIVER / DESIGN VIEW

Measure the time.Recover the letters.

Reception is more than detecting a signal. It means distinguishing pulses, gaps within a letter and pauses between letters, then preparing the OLED output.

  • Timing
  • OOK
  • I²C OLED
  • Calibration

The approach

Silence is part of the message

An isolated pulse is not yet a letter. The receiver needs its duration, but also needs to know when the sequence ends. A short gap separates symbols; a longer one closes a letter, then a word. The approach is to test a known sequence on the prototype and compare its interpretation with the expected result. The documents report working timing-based decoding and OLED output on that prototype. Moving to a custom board adds radio-module levels, possible unwanted signals and threshold adjustment to the problem. Reception between the two dedicated PCBs still needed calibration and validation at the end of the project.

04 / EMBEDDED LOGIC / TEAM PCB

Detect a change, without promising correction

Development
Embedded C, STM32CubeIDE / CubeMX.
Repository CRC
8 bits · polynomial 0x07 · initial value 0x00.
Reproducible example
CRC-8 of “SOS” = 0xBF.

CRC processes the message bytes with XOR and shifts. A receiver can recompute the value and compare it with the transmitted one. A mismatch indicates an inconsistency; a match does not guarantee detection of every possible corruption. CRC does not restore corrupted data.

The presentation illustrates Morse durations; the public repository supplies an isolated CRC routine. Suggested frame formats in the notes do not establish final integration. The animation below uses the real CRC calculation, while the Morse animation explains standard timing conventions.

Interactive bench 03 · CRC-8

Change one bit. Compare the CRC.

A compact check can reveal an altered message. Flip a bit in one ASCII byte and compare the reference CRC with the value calculated from the received data.

01 / BEFORE SENDING

A small fingerprint.

The sender turns the message’s bytes into one extra byte: the CRC. For SOS, the ASCII bytes 53 4F 53 give 0xBF. The same data always give the same result with this algorithm.

02 / AFTER RECEIVING

Recalculate. Compare.

The receiver runs the same calculation on the bytes it received, then compares the result with the transmitted CRC. Flip a bit below: the message changes, and the recomputed CRC can reveal the difference.

03 / WHAT IT TELLS US

An alert, not a repair.

A mismatch means an error was detected. The CRC cannot tell which bit to fix. Because an 8-bit check has only 256 possible values, different messages can share a CRC: a match is useful evidence, not an absolute guarantee.

C / FROM THE TEAM REPOSITORYOpen the source ↗
uint8_t crc = 0x00;
const uint8_t poly = 0x07;

for (size_t i = 0; i < len; i++) {
    crc ^= data[i];
    for (int b = 0; b < 8; b++) {
        if (crc & 0x80) crc = (uint8_t)((crc << 1) ^ poly);
        else           crc = (uint8_t)(crc << 1);
    }
}
return crc;

Read the code in four steps.

  1. Start at zero. crc = 0x00 creates the 8-bit working register.
  2. Add one byte. crc ^= data[i] XORs the next message byte into it: a bit becomes 1 when the two inputs differ.
  3. Process its eight bits. Each iteration shifts the register left. If its previous leftmost bit was 1, XOR with 0x07. The uint8_t cast keeps only eight bits.
  4. Continue, then return. Repeat for every message byte. The final register value is the CRC.

Why 0x07? It represents the lower terms of the chosen polynomial, x8 + x2 + x + 1. The x8 term is implicit in an 8-bit CRC.

Look inside one byte, step by step +

For a single S, ASCII is 0x53, or 01010011. Starting from zero, XOR gives 0x53; eight shifts produce 0xBE. For SOS, the calculation continues with O and S, giving 0xBF.

The approach

Find where the chain stops

When an assembly does not yet work, locating the relevant block is more useful than changing the whole system at once. Here, timing-based decoding could be tested on a development board, and a piezo signal was measured on the transmitter PCB. Hardware integration took longer than planned: excess solder paste caused shorts after reflow, and late deliveries reduced the time available. These issues required changes to the schedule. The next logical steps are to inspect the assembly, finish the antennas, calibrate reception and then test a known message across the complete chain. The conclusion stays specific: several blocks were demonstrated; the complete link between the dedicated PCBs was not.
