01 / DEUX CARTES, UNE CHAÎNE

Du capteur à la lettre

Contexte
Projet collectif de 2026, réalisé à six.
Mon rôle
Traitement et logique embarquée, avec Tristan.
Sens de la liaison
Émetteur → récepteur ; communication unidirectionnelle.

Un piézo est associé au point, l’autre au trait. La carte émettrice doit transformer les impacts détectés en impulsions cohérentes. Le récepteur doit ensuite mesurer les périodes actives et les silences pour reconstruire les caractères ; l’OLED I²C est prévu pour les afficher.

Les points et les traits utilisent la même porteuse à 433,92 MHz. L’information est portée par les durées : en OOK, la porteuse est activée puis coupée. Le projet ne repose donc pas sur une fréquence radio différente pour chaque symbole.

01 / DEUX CARTES, UNE CHAÎNE

Un geste.Un message.

Deux piézos, deux cartes STM32 et une liaison radio à 433,92 MHz. L’objectif : transformer des frappes en points et traits, puis retrouver des lettres sur un écran.

  • Piézos
  • STM32
  • 433,92 MHz
  • OOK

La démarche

Relier les blocs, sans perdre le signal

Le point de départ est volontairement simple : on frappe l’un des deux capteurs piézo pour saisir un point ou un trait. Derrière ce geste se trouve une chaîne complète, avec une entrée à interpréter, une durée à produire, une porteuse radio à commander et des lettres à reconstruire. Nous avons réparti ces blocs dans une équipe de six. Avec Tristan, j’ai travaillé sur le traitement et la logique embarquée. La première question était de savoir ce que chaque bloc devait recevoir et fournir au suivant. Le prototype a permis de vérifier l’interprétation temporelle du Morse avant l’intégration finale. Les deux PCB photographiés matérialisent cette architecture ; leur fabrication ne signifie toutefois pas que la liaison radio complète ait été validée.

02 / ÉMETTEUR / VUE DE CONCEPTION

Détecter l’impact.Donner le rythme.

La carte rassemble le STM32, l’alimentation et les connexions des piézos et du module radio. Un signal piézo a été mesuré sur ce PCB pendant les essais.

  • Acquisition
  • 3,3 V
  • SWD
  • Conception KiCad

La démarche

Une frappe doit devenir un événement clair

Un capteur piézo réagit à une vibration : le logiciel doit en tirer un événement exploitable, puis produire un symbole court ou long. L’enjeu est de distinguer une frappe utile d’un signal parasite sans multiplier les déclenchements. Le prototype sert à comprendre cette logique ; les mesures sur la carte émettrice permettent ensuite d’observer ce qui arrive réellement depuis le capteur. Le rapport décrit un signal piézo envoyé et mesuré sur le PCB. C’est une étape concrète pour l’acquisition, mais elle ne suffit pas à démontrer une transmission radio décodée à l’autre bout. Pour avancer simplement, il faut vérifier l’entrée, la durée du symbole et la sortie vers le module radio comme trois éléments distincts.

03 / RÉCEPTEUR / VUE DE CONCEPTION

Mesurer le temps.Retrouver les lettres.

La réception ne consiste pas seulement à voir un signal. Il faut distinguer les impulsions, les silences entre symboles et les pauses entre lettres, puis préparer l’affichage sur l’OLED.

  • Durées
  • OOK
  • OLED I²C
  • Calibration

La démarche

Le silence fait aussi partie du message

Une impulsion isolée ne donne pas encore une lettre. Le récepteur doit connaître sa durée, mais aussi savoir quand la séquence est terminée. Un silence court sépare les symboles ; un silence plus long ferme une lettre, puis un mot. La démarche consiste à tester d’abord une séquence connue sur le prototype et à comparer l’interprétation obtenue avec celle attendue. Les documents rapportent un décodage temporel et un affichage OLED fonctionnels sur ce prototype. La migration vers la carte dédiée ajoute cependant les niveaux du module radio, ses parasites éventuels et le réglage des seuils. La réception entre les deux PCB restait à calibrer et à valider à la fin du projet.

04 / LOGIQUE EMBARQUÉE / PCB DU GROUPE

Détecter une erreur, sans promettre une correction

Développement
C embarqué, STM32CubeIDE / CubeMX.
CRC du dépôt
8 bits · polynôme 0x07 · initialisation 0x00.
Exemple vérifiable
CRC-8 de « SOS » = 0xBF.

Le CRC parcourt les octets du message à l’aide de XOR et de décalages. Le récepteur peut recalculer la valeur et la comparer à celle transmise. Une différence indique une incohérence ; une égalité ne garantit pas la détection de toutes les altérations possibles. Le CRC ne restaure pas les données corrompues.

La présentation illustre des durées de Morse ; le dépôt public fournit une routine CRC isolée. Les exemples de structure de trame dans les notes ne prouvent pas leur intégration finale. L’animation ci-dessous reprend le calcul réel du CRC, tandis que l’animation Morse montre la convention temporelle standard.

La démarche

Du prototype au code disponible

Atelier interactif 03 · CRC-8

Un bit change. Le CRC aussi.

Un petit contrôle peut révéler un message altéré. Inversez un bit dans un octet ASCII, puis comparez le CRC de référence à celui recalculé sur les données reçues.

01 / AVANT L’ENVOI

Une petite empreinte.

L’émetteur transforme les octets du message en un octet supplémentaire : le CRC. Pour SOS, les octets ASCII 53 4F 53 donnent 0xBF. Avec cet algorithme, les mêmes données donnent toujours le même résultat.

02 / APRÈS RÉCEPTION

Recalculer. Comparer.

Le récepteur refait le même calcul sur les octets reçus, puis compare le résultat au CRC transmis. Inversez un bit ci-dessous : le message change, et le CRC recalculé peut révéler cette différence.

03 / CE QU’ON APPREND

Une alerte, pas une réparation.

Deux CRC différents indiquent une erreur détectée. Le CRC ne dit pas quel bit corriger. Un contrôle sur 8 bits n’a que 256 valeurs possibles : des messages différents peuvent partager un CRC. Une égalité est donc utile, sans constituer une garantie absolue.

Les données de référence et les données reçues donnent le même CRC. Ce contrôle est illustratif, pas un essai matériel.

C / DÉPÔT DE L’ÉQUIPEOuvrir le code ↗
uint8_t crc = 0x00;
const uint8_t poly = 0x07;

for (size_t i = 0; i < len; i++) {
    crc ^= data[i];
    for (int b = 0; b < 8; b++) {
        if (crc & 0x80) crc = (uint8_t)((crc << 1) ^ poly);
        else           crc = (uint8_t)(crc << 1);
    }
}
return crc;

Lire le code en quatre étapes.

  1. Partir de zéro. crc = 0x00 crée le registre de travail sur 8 bits.
  2. Ajouter un octet. crc ^= data[i] combine le prochain octet avec le registre par XOR : un bit vaut 1 quand les deux entrées sont différentes.
  3. Traiter ses huit bits. À chaque tour, le registre est décalé à gauche. Si son ancien bit de gauche valait 1, on applique un XOR avec 0x07. La conversion uint8_t ne conserve que huit bits.
  4. Continuer, puis renvoyer. On recommence pour chaque octet du message. La dernière valeur du registre est le CRC.

Pourquoi 0x07 ? Cette valeur représente les termes de degré inférieur du polynôme choisi, x8 + x2 + x + 1. Le terme x8 est implicite pour ce CRC sur 8 bits.

Entrer dans un octet, étape par étape +

Pour un seul S, l’ASCII vaut 0x53, soit 01010011. En partant de zéro, le XOR donne 0x53 ; huit décalages produisent 0xBE. Pour SOS, le calcul continue avec O puis S et donne 0xBF.

Départ : 0x00 XOR octet. Le registre prend la valeur de cet octet.

Cette vue isole l’octet choisi plus haut. Dans un message de plusieurs octets, le registre garde le résultat du précédent : il ne repart pas de zéro.

La démarche

Comprendre où la chaîne s’arrête

Quand un ensemble ne fonctionne pas encore, il est plus utile de localiser le bloc en cause que de modifier tout le système à la fois. Ici, le décodage temporel a pu être testé sur une carte de développement, et un signal piézo a été mesuré sur la carte émettrice. L’intégration matérielle a pris plus de temps que prévu : un excès de pâte à braser a provoqué des courts-circuits après refusion, et des livraisons tardives ont réduit le temps disponible. Ces problèmes ont conduit à revoir le planning. La suite logique consiste à contrôler l’assemblage, terminer les antennes, régler la réception puis essayer un message connu de bout en bout. Le bilan reste précis : plusieurs blocs ont été démontrés, la liaison complète entre les PCB ne l’a pas encore été.
